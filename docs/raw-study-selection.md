# Frozen raw development selection

The raw workflow can freeze one development choice after all eight original candidate/cost trials succeed. It follows the rule already declared in [the original raw plan](raw-universe-study-declaration.md); it does not add a candidate search or grant a final evaluation.

`POST /api/research/raw-studies/{id}/select` accepts `{ requestId, planSha256 }`. Selection requires `development-complete` and the current scientific/Core/runtime identity. It checks every original request and immutable report hash and retains the eight registry trial IDs, logical roles, request digests and report digests. The worker independently reconstructed and replayed each report before publication. Selection reads those sealed artifacts and performs arithmetic; it neither reexecutes source data nor opens final-window observations. A standalone list of externally supplied metric observations does not acquire this provenance merely by passing the pure arithmetic helper.

For each candidate and each base/stress scenario, compare momentum ending GBP wealth with the better of that scenario's equal-weight and cash accounts. Score the candidate by its smaller base/stress margin. Choose the largest score, breaking ties by ordinal candidate ID. All four scores, all original hashes and the frozen rule remain in the selection artifact; failed or missing trials cannot be removed to rank only successes.

A genuine-provenance family requires a strictly positive worst margin; otherwise it records `no-candidate` and releases its two unspent reserved slots while retaining every development exposure/trial. A synthetic family may record a nonpositive choice for lifecycle rehearsal only. This point-estimate convention does not adjust uncertainty, validate data, approve an investment strategy or establish profitability. Existing search-aware diagnostics remain separately scoped; whole-programme correction remains open.

A successful result is stored as an immutable content-addressed artifact and atomically bound to the parent as `candidate-frozen` or `no-candidate`. The same UUID returns the original outcome after restart or scientific code changes. A replacement UUID cannot rerank the family. Cancellation retains successful reports and selection evidence. Active frozen candidates retain their final-window reservation. No raw final claim is spent, no paper account is promoted, and no broker authority is created.

`GET /api/research/raw-studies/{id}/selection` returns the hash-checked artifact and validates its original parent/trial bindings. Historical inspection checks stored provenance without reinterpreting old results under new code. The history endpoint advertises `selectionAvailable: true`, `finalEvaluationAvailable: true`; the existing same-origin/header write guard and 16 KiB host body limit remain. The separate [one-time raw final endpoint](raw-study-final.md) now spends the permanent claim; selection itself grants no final calculation. Graphical raw-plan authoring remains unimplemented.

Authored tests cover robust stress margin versus tempting base upside, deterministic synthetic ties, genuine no-candidate behaviour, complete family coverage, reused artifacts, corrupt report refusal, original UUID replay, replacement rejection and byte-identical selection/report recovery. A deliberate upside-only ranking mutation fails its regression; restored code passes. The original raw trial count remains eight through selection; no genuine holdout is used for acceptance.
