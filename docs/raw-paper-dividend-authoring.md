# Cash-dividend paper account authoring

29 October 2026. The Paper accounts creation form now offers **Cash dividends** alongside **No corporate actions** and **Stock splits**. It supplies the existing [cash-dividend catalog](raw-paper-dividends.md) through labelled fields, with add/remove controls for multiple actions. This closes graphical term authoring for the existing bounded mode; it adds no new accounting policy.

Every row binds a listing, action and observation, cutoff time/availability/source/hash, payment ID/time/availability/source/hash, currency, gross and withheld amounts per cutoff share, one fixed GBP fee per entitled account and an optional payment FX observation ID. UTC timestamps include seconds and `Z` or `+00:00`. The form binds the booking metadata to the chosen dataset and fixes the existing allocation rule; canonical replay IDs and ordering remain the server's responsibility. Original evidence must already exist: entering a reference does not collect or verify a vendor statement.

Monetary inputs remain strings in the browser. The serializer validates nonnegative, bounded decimal tokens and emits them directly as JSON numbers, preserving up to 28 fractional digits within `System.Decimal`'s coefficient range. It never converts these terms through JavaScript `Number`. Gross must be positive and withholding cannot exceed it. Identity strings are JSON-escaped. The API still independently checks the entire dataset/catalog/action/payment contract before freezing the account. HTML required fields and local validation do not replace that admission.

The dividend choice requires `actionSupport.dividends: true`, `dividendMode: "cash-dividends-v1"` and `dividendScope: "paid-before-monthly-marks"`. An older server or an unfamiliar scope/mode does not offer it. Default requests omit both `actionMode` and `dividends`; split requests omit `dividends`, including after editing dividend rows then changing mode. An unchanged retry keeps the same request UUID. Account creation is permanent for each study/cost pair; it does not upgrade or reset an existing account. Preparation still shows a projection; application is separate and explicit.
