## Registered universe-backtest trials (19 October 2026)

Changing-universe backtests are now registerable trials. `ResearchStore` gained a `universe_runs` register (partial class, same SQLite/lease/event discipline as runs and studies): datasets import content-addressed after validation, each attempt is inserted `started` before computation and reaches one terminal state, failed attempts (gap panels, missing terminal proceeds) are retained with their refusal code and panel hash, request-id replay returns the original entry and semantic changes conflict, and store reopening marks stale `started` rows `interrupted`. Reports are immutable and hash-verified on read. HTTP endpoints under `/api/research/universe-runs` expose import, execution and retrieval; capabilities advertise `changingUniverse.registeredTrials`. Six new store tests cover success/replay/conflict/retained-failure/unknown-dataset/restart/tamper paths (387 .NET tests total). The register is deliberately separate from frozen studies and diagnostics; offline CLI runs remain unregistered exploratory output.

## Independent FX producer comparison: ECB vs Bank of England (19 October 2026)

`scripts/audit_fx_ecb_boe.py` compares the ECB eurofxref history against Bank of England daily spot rates into sterling (`XUDLUSS`/`XUDLERS`), retiring the same-producer caveat for the FX legs. Over the pre-declared calendar-2024 window (253 matched dates): USD-per-GBP median difference −0.33 bp, EUR-per-GBP +0.24 bp — direction, scale and units agree across independent official producers; ECB-only dates are UK bank holidays and the sole BoE-only date is 1 May. Dispersion is fixing-time noise (p95 45.5 bp USD; nine >50 bp dates on US-release/Budget days, max 105 bp), reinforcing that reference rates are not execution prices. Arithmetic was corroborated two ways for 2024-06-03 (+33.712 bp both). Three unit tests pin hand arithmetic, inverted-quote detection and fail-closed parsing. Payload hashes and full results: `docs/fx-independent-audit.json`; raw payloads stay outside Git.

## Quark Intel iGPU benchmark (18 October 2026)

PyTorch XPU was validated on Quark's Arrow Lake-S iGPU from an isolated `.venv-xpu` (torch 2.12.1+xpu) with Fedora Level Zero/NEO userland extracted into the environment — no system packages installed, no sudo, project `.venv` and the deployed container untouched. The committed benchmark (`scripts/benchmark_accelerator.py`, 3 CPU-safe helper tests) trains Twenty's actual `Neural` MLP on deterministic authored rows under declared bounds (4 CPU threads, 3 repeats). Real-device results: XPU available with working kernels; prediction parity vs CPU near-exact (correlation 1.000000, max difference ≤1.9e-8, criteria declared in advance); fit speedup 0.26× at 6k rows, 2.49× at 120k and 3.73× at 900k, with first-fit JIT costs up to 208 s and ~3.0 GB peak RSS vs 0.7–1.2 GB on CPU. Verdict: CPU remains the default — Twenty's real training sets are thousands of rows, where the iGPU is slower. Full setup, failure modes (CUDA wheel reports zero devices; missing `libigc.so.2` symlink breaks kernel builds) and numbers in the [iGPU benchmark record](quark-igpu-benchmark-2026-10-18.md). Inputs were synthetic; this is an engineering measurement, not strategy evidence. Local validation passes 355 .NET tests and the Python suite (25 tests; the three torch-gated tests run where the optional neural dependency is installed and skip in clean environments), Ruff, Svelte check/build, the research-boundary probe, the dataset validator, the SEC/ECB inspectors and the sensitive-path guard.

## Small-workload timing observation

Each model evaluated 141 monthly intervals after the same initial training history, using eight synthetic assets and a synthetic benchmark. The final 24 return intervals remained reserved. The neural models used 60 full-batch training epochs per refit and the same seed/architecture. Runs were sequential.

| Model | Training device | Experiment runtime | Total fit time |
|---|---|---:|---:|
| Ridge | CPU | 0.031 s | 0.001 s |
| Small neural network | CPU | 0.661 s | 0.623 s |
| Small neural network | Apple MPS GPU | 3.844 s | 3.519 s |

These are single-run smoke measurements, not a controlled hardware benchmark or a prediction of larger-workload performance. Experiment timing excludes interpreter startup and the initial device-availability check; fit timing includes device synchronisation. The same neural allocation decisions resulted on CPU and MPS for this fixture. General numerical parity and repeatability across accelerators are not established.

The fixture has no real financial content. Neither these timings nor the resulting portfolios demonstrate forecasting skill, profitability or a route to £1 million.

The observations support using CPU as the default at this scale. Profile a representative real dataset before adding accelerated scenario simulation or selecting a training accelerator.
