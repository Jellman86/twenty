# Pending terminal claims in authored paper accounts

29 October 2026. `terminal-claims-v1` creates `raw-paper-terminal-claim-batches-v1`. This separate mode extends the existing CPU terminal accounting and claim planner into complete authored paper batches. The original [settled-terminal mode](raw-paper-terminals.md) still refuses unpaid monthly boundaries. No Core, engine, archive or report version changes, genuine financial acceptance, broker execution or final holdout use are introduced.

## Frozen contract and timing

Each frozen `terminals` row retains explicit cutoff evidence and actual zero/cash/stock settlement. Optional `markPolicy` binds independent expected withholding per cutoff share, expected fixed GBP fee per entitled account, availability, source reference, content hash and `raw-study-claim-mark-per-share-fixed-gbp-fee-v1`. Cash requires matching currency; stock uses null currency and zero cash withholding. Confirmed zero has no delivery or mark policy. The original settled mode refuses a supplied mark policy instead of ignoring it.

Capture uses the latest of effectiveness, action availability and cutoff-proof availability. Settlement uses the latest of capture, actual settlement and settlement-evidence availability. A claim crossing any monthly boundary, including the first decision, needs expected-policy evidence available by its first such boundary. Every captured claim must settle by the last account mark, including exact-boundary settlement before marking. Missing/late expectations and final unpaid claims refuse at creation; the same checks run during preparation. Evidence hashes bind authored inputs without authenticating legal entitlement. Actual future settlement deductions or FX cannot improve earlier expected marks.

The existing shared ledger determines cutoff ownership. Per-share terms become total assumptions exactly once; the fixed fee applies once per entitled account. Complete pending marks cover every owned unsettled claim. Expected value participates in target sizing, but cannot fund purchases or sell undelivered shares. Expected stock fees reserve actual cash. A higher unexpected actual fee refuses borrowing and leaves accepted state unchanged. Zero ownership produces no estimate or actual fee. Capacity, work, ordering, canonical batch binding, UUID/head and interrupted-publication guards remain.

`equityGbp` remains delivered holdings plus settled cash. New-mode balances additionally carry `terminalClaims: {count,netExpectedValueGbp,expectedFeesGbp,expectedEquityGbp}`. Estimated fees remain distinct from cumulative actual fees. Pending dividends and terminal summaries are mutually exclusive; other modes omit this field. Corrupt, mixed, missing or arithmetically inconsistent summaries refuse inspection. Old artifacts are not rewritten. Research code identity changes, so old accounts remain inspectable/retryable but cannot continue under changed science.
