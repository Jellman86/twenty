# Sidebar shell, plain-language labels and colour themes

Implemented 29 October 2026 at the owner's request: replace the top navigation with a sidebar, fill large displays, support light and dark modes, and make the purpose of each page clear. The owner named midnite.com as visual inspiration. That site blocks automated browsers, so the design takes only its measurable traits: a graphite base (`#161718`), grey secondary text, Inter-first type, high contrast, compact square tiles and a single vivid accent. Midnite's brand colours were not copied; Twenty keeps its ember accent.

## Layout

- **Wide windows (over 1100 px):** a 264 px sidebar with two groups. **Trading** has Portfolio, Activity and Orders. **Strategy lab** has Research and Paper trading. Settings sits at the bottom. Each item has a one-line description. The order-mode card explains what the mode means (for example, *Research only* means that order execution is off).
- **Medium windows (721–1100 px):** an 88 px icon rail with short labels.
- **Phones (720 px and under):** a top bar with the mode and theme switch, plus a six-item bottom tab bar.
- Content has no maximum width, so it fills the window. Page grids use container queries on `main` rather than viewport breakpoints, because the sidebar takes part of the width.
- Every page header has an eyebrow (its group), a title and a one-sentence lede. *Paper accounts* is now shown as **Paper trading**. When the server reports `authoredOnly`, a callout says that balances use made-up prices and say nothing about returns. API routes and hashes (`#paper` and others) are unchanged.
- Roadmap and Evidence remain in the Research sub-navigation, styled as secondary links. They are not part of the main navigation.

## Themes

`:root` holds the dark tokens, and `:root[data-theme=light]` overrides them. Accent-coloured text uses `--ember-text`, so small text keeps AA contrast on white. The control offers *Match this device*, *Light* and *Dark*. An explicit choice is stored in `localStorage['twenty-theme']`, and *Match this device* clears it. `/theme-init.js`, served from `web/public`, applies the theme before first paint. It is a same-origin file because the Content-Security-Policy keeps `script-src 'self'` with no inline scripts.

## Verification

`scripts/ui_workflow_check.py` now asserts:

- the sidebar at 2560 and 1440 px, the rail at 1024 px and the bottom tab bar at 390 px;
- content reaching the right edge;
- group labels and descriptions;
- the test-data callout;
- theme behaviour: following the device's light or dark setting, switching, and persistence across reloads.

It ran against a private loopback copy of the authored split fixture, with synthetic broker responses. Evidence lives outside Git under `artifacts/twenty/ui-sidebar-20261029/`.

Not verified: real devices (only Chromium in Playwright was used), Safari/WebKit `color-mix` rendering, a screen-reader pass, and the production deployment.
